## Confirmed defects and change scope

- The current card parser was already present, but both document fields used the pass number and discarded the separate permit. Haryana now uses the printed permit as docNo and the transport pass as tpPassNo. Those are distinct document and transport identifiers, not an invented invoice number.
- Haryana QR rows did not carry the existing canonical quantity marker. The legacy QR handoff could treat a nonzero loose-bottle count as the entire quantity and drop printed cases. Haryana now uses the existing canonical case/loose contract; PL is never a quantity source.
- The previous failure message combined blank responses, browser failure, and parsing failure into no_html_rows. Haryana retrieval now reports bounded stage/status/size/timing diagnostics without government URL tokens, cookies or HTML; access gates, malformed products, network errors and browser errors are distinct.
- HTTP cards remain the fast path. There are at most two HTTP attempts, a validated redirect chain with shared cookies, a bounded browser fallback with one browser per API process, and a 100-second total ceiling. No new authentication bypass is introduced.
- Complete encrypted source URLs are preserved in the job rather than truncated to 240 characters. HTTPX URL logging for this government endpoint is suppressed to protect encrypted query values.
- Other state parsing, mapping records, Calculate-owned values, Purchase Save, proxies and databases are not changed. The universal handoff schema remains intact. Financial values absent from the source remain null in the source-financial fields.
